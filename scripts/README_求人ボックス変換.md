# 他媒体の求人原稿 → 求人ボックス採用ボード CSV 変換

AirWork等からエクスポートした求人を、求人ボックス「直接投稿（採用ボード）」のCSV一括更新用に変換する。
1原稿をターゲットペルソナ別に3原稿へ複製し、重複判定を避けるための差別化も行う。

---

## 運用ルール（この文書の位置づけ）

**この文書が変換仕様の正。** 「このCSVを求人ボックス用に変換して」と言われたら、まずここを読んでから作業する。

- 新しい制約や仕様の誤りが判明したら、**その場でこの文書を更新する**。会話の中だけに留めない
- 判明の経路は問わない（アップロードのエラー、媒体側からの連絡、審査の指摘、実CSVとの差分など）
- 更新したら「どこを・なぜ変えたか」を必ず報告する
- 公式マニュアルとこの文書が食い違う場合、**実際に通った実績があるこの文書を優先する**

### 新しい媒体の初回だけは調査が要る

AirWork以外のエクスポートを渡された場合、初回はヘッダー構成を読んで項目マッピングを組む必要がある
（→「新しい媒体を追加するには」）。2回目以降はコマンド一発。

## クライアント別のルール

### 株式会社TAKE FOUR（派遣）

2026-09-03 に本人から出た変更依頼をルール化したもの。**新しい求人でも毎回これを適用する。**

**勤務地に派遣先の情報を出さない**
- `交通手段・勤務地補足` に派遣先企業名を書かない（例: 「【勤務先】関東モリ工業株式会社」は不可）
  → 代わりに「※勤務先の詳細は面接時にご案内します。」を添える
- `勤務地_詳細_1` は**町名まで**。番地は書かない（「常総市大塚戸町1786」→「常総市大塚戸町」）
- 元のPDFには派遣先名も番地も書いてあるが、**求人票には出さない**のが方針

**給与の書き方**
- 資格や条件で時給が変わる場合、`仕事内容` にも金額を明記する（給与欄だけに留めない）
- 実働時間と給与計算の時間が違う場合は明記する（例: 「実働7時間55分ですが、給与は8時間分をお支払いします」）
- **月収例を必ず入れる。** 前提条件（勤務日数・残業時間）も併記する

  ```
  【月収例】
  資格なし 月収250,125円
  （時給1,450円×8時間×20日＋残業10時間）
  ```

**PRの方向性**
- 資格取得支援など、先方が推したい点は `対象となる方` の冒頭に置く。
  ペルソナ複製でPR欄にも流れるので、これで十分伝わる
- 文体は通常のトーンでよい。ただし**内容は落とさない**
- 独立したPR枠として前面に出したい場合は、`extra_jobs.json` に `_pr` を書くと
  PR欄の先頭に固定できる（ペルソナ共通）。強い訴求が1つだけある求人向け
- なお `！` はタイトルでは使えないが**本文・PR欄では使える**。
  タイトルの記号制限を本文にまで広げないこと

**その他**
- 「外国籍可」と原稿にあっても記載しない（2026-08-28 の依頼）。
  書かないだけで、応募を制限する記述は入れない
- 年齢・性別の条件が原稿にあっても出力しない（法令。全クライアント共通）

## ファイル構成

|---|---|
| `airwork_to_kyujinbox.js` | 本体。項目マッピング・定型文除去・出力カラム選定・重複チェック |

| `extra_jobs.json` | PDF等からデータ化した、AirWorkに無い求人を合流させる |

## 使い方

### 新規投稿

`--ref` に管理画面のダウンロードタブから取得したCSVを渡すと、そのヘッダー行に完全一致させる。

```bash
node scripts/airwork_to_kyujinbox.js \
  ~/Downloads/AirWork求人リスト.xlsx \
  出力.csv \
  --ref ~/Downloads/P-xxx-xxx_saiyoboard_kyujin_YYYYMMDDHHMM.csv
```

### 既存求人の更新

`--update` に最新のダウンロードCSVを渡すと、`メモ` 欄をキーに `求人ID` を引き当てる。
`メモ` には `AW:12485617/経験者` のように「元求人ID + ペルソナ名」が入っており、変種ごとに一意。

```bash
node scripts/airwork_to_kyujinbox.js \
  ~/Downloads/AirWork求人リスト.xlsx \
  出力.csv \
  --update ~/Downloads/P-xxx-xxx_saiyoboard_kyujin_YYYYMMDDHHMM.csv
```

更新モードでは `--ref` を付けない。理由は下記「更新時の空カラム」を参照。

## 重要な注意点

### 公式マニュアルの記載は信用しない

`https://saiyo.kyujinbox.com/ptr/csvupload_manual.pdf`（ver.1.3）には**誤りがある**。
実際に受け付けられる列名は、管理画面のダウンロードタブから落としたCSVのヘッダー行が正。

| マニュアルの記載 | 実際に通る名前 |
|---|---|
| `求人作成日`（仕様表 p.30） | **`求人作成日時`** |
| `特徴`（記入例 p.42） | **`求人の特徴`** |

どちらも「使用できない項目名が含まれています」で弾かれた実績あり。
仕様が変わった疑いがあれば、まず最新CSVを1本落として `--ref` に渡すこと。

### 求人タイトルで使える記号は `・` `／` `「」` のみ

`【】` `｜` `＆` `（）` 半角括弧 `()` 桁区切りカンマ はすべて不可。
`personas.js` の `sanitizeTitle()` が変換・除去する。元原稿のタイトルにも半角括弧が混ざっているので要注意。

※マニュアルp.28は禁止記号の列挙だが、実際の審査はより厳しい許可制。

### 労働者派遣業の許可番号は絶対に消さない

`※労働者派遣業（派）08-300957` は労働者派遣法上の表示事項。
AirWork原稿ではQRコードの商標表記と同じブロックに同居している場合があり、
ブロック単位で消すと巻き添えになる。`法定表示` 正規表現で保護している。

### 更新時の空カラム

マニュアルp.12：**指定した列が空欄だと、既存の値が消える。**
そのため更新モードでは値のある列だけを送る（`selectColumns()`）。
`--ref` を併用すると全56列を送ることになり、管理画面で手動設定した項目が消えるので注意。

### 年齢・性別による絞り込みは書かない

- 雇用対策法10条：募集・採用時の年齢制限は原則禁止
- 男女雇用機会均等法5条：募集・採用時の性別限定は原則禁止

若年層からの応募は「制限」ではなく訴求内容（未経験歓迎・高収入・土日祝休み等）で寄せる。
元原稿に「性別:男性」「年齢:20〜60歳」とあっても出力しない。

### 原稿に無い事実は足さない

装飾文言・訴求文はすべて元原稿から抽出した fact に紐づく場合のみ出力する。
`extractFacts()` が求人の特徴タグ・給与・休日から fact を抽出し、
裏付けのあるバッジだけをタイトル・やりがい欄に使う。

## 求人ボックス推奨の原稿ルール

出典は末尾「公式ガイド」の4資料。

> **これは「推奨」であって「必須」ではない。**
> 守らなくてもアップロードは通るし、掲載もされる。原稿を作る際の参考にする位置づけ。
> 機械的に強制すると、かえって原稿が痩せたり変種のタイトルが同一化したりして逆効果になる。
> 迷ったら**推奨より実害の回避を優先**する（例：30字に詰めるためにバッジを削って
> 3変種のタイトルが同じになるくらいなら、35字でも差別化を取る）。
>
> **必須なのは以下の3つだけ。** これらは違反するとアップロードが弾かれるか、法令違反になる。
> - CSV仕様（列名・マスタ値・文字数上限）→ `validate.js` がエラーとして検出
> - タイトルの使用記号 `「」／・` → 自動整形でタイトルが削除される可能性がある
> - 年齢・性別による絞り込みを書かない → 雇用対策法10条・男女雇用機会均等法5条
>
> 実行時、推奨から外れた点は `💡` で表示されるが、これは**情報提供であって修正必須ではない**。

### タイトル

| ルール | 内容 |
|---|---|
| **30文字以内** | 検索結果画面で見切れる。CSVの上限は75文字だが、実用上の目標は30文字 |
| **記号は `「」` `／` `・` のみ** | それ以外は非推奨。`【】＜＞※！～` など。**キーワードが自動整形され、タイトルが削除される可能性がある** |
| 職種名は具体的に | ✕「警備員」「事務スタッフ」「介護スタッフ」→ ○「日勤のみの施設内警備スタッフ」「物流業界の経理・総務事務」 |
| 未経験向けなら未経験者が想像できる言葉に | ✕インサイドセールス → ○取引先への法人営業・訪問なし ／ ✕生産社員 → ○自動車部品工場での生産管理 |
| 経験・資格が必須なら明記 | `CADオペレーター／経験3年以上` — アンマッチなクリックを排除できる |
| 職種名＋メリットの構成 | 職種だけでなく条件面・メリットを盛り込む |

### 抽象語を使わず、具体・定量で書く

「福利厚生充実」「安定」「高収入」「アットホームな雰囲気」は**誰でも書けるので差別化にならない**。

| ✕ 抽象 | ○ 具体 |
|---|---|
| 福利厚生充実 | 社食1食130円、住宅手当月5万、賞与去年度実績6か月分 |
| 安定・高収入 | プライム上場、業界シェアトップ、入社1年目から420万可 |
| シフト制 | 連休OKのシフト制、平均月8日休みのシフト制 |

### メリットキーワードには強弱がある（強い順）

- 土日休み・土日祝休み ＞ 完全週休2日制 ＞ 週休2日制・日曜固定休の週休2日制
- 残業なし ＞ 残業ほぼなし ＞ 残業少なめ
- 希望シフト制・自由シフト制 ＞ 希望休OK・月○日希望休あり ＞ 希望休を反映
- 有給自由取得・消化率○% ＞ 有給取得しやすい ＞ 有給休暇あり

### 使わないワード

- **「急募」は非推奨**。「いつでも入れる」「なかなか採用できない」「すぐ辞める」という印象を与える。
  代用: 「即日勤務可」「事業好調／積極増員中」
- **「経験者優遇・未経験者も歓迎」はNG**。経験者と未経験者では見せ方を変える
  （経験者向け＝専門用語、未経験者向け＝教育体制と平易な説明）
  → 本ツールのペルソナ複製はこの指摘に沿った設計になっている

### タイトルに書く優先度が低いもの

原稿本文に記載があれば求人ボックス側で一覧に自動表示される可能性が高いため、タイトル枠を使うのはもったいない。

- 正社員で本文に賞与・昇給の記載 → 「賞与あり・昇給あり」が自動表示
- パート/アルバイトで本文に交通費の記載 → 「交通費支給」が自動表示

ただし「賞与年3回」「去年度実績6か月分」のように大きなメリットになる場合は書く。

### ターゲットは明確で狭いほうがよい

「主婦でもシニアでも学生でもいい」ではなく「単位取得済みの大学3〜4年生を歓迎」のように絞る。
ターゲットごとに伝えることを変える（例：ブランクOK＋50代60代活躍中／週2〜3日OK＋シフト制）。

### 応募フォームの使い分け

入力項目が多いほど応募のハードルが上がり応募率は下がる。

| 設定 | 向いているケース |
|---|---|
| 氏名・連絡先のみ | 経験・学歴不問、アルバイト・パート、大量募集、**採用競争が激しい業界や職種** |
| 基本情報 | 正社員募集、応募条件あり（経験・資格必須） |
| 基本情報＋職務経歴 | 書類選考を実施、応募をある程度絞りたい |

### 写真が掲載順位に影響する

アルゴリズム更新により**画像の有無が掲載順位の要素**になっている。職場写真は6枚まで登録可能。
本ツールは `写真ID` を出力しない（元データにないため）。順位を上げるなら管理画面での登録が必要。

### 職種別の押さえどころ（本ツールで扱う職種）

**製造・機械オペレーター**
- 具体的な作業工程、扱う製品、**商材の大きさ・重さ**（例：5g〜100g程度の軽量部品）
- 作業スタッフの人数・男女比・年齢層（例：20〜50代の男女4名が活躍中）
- 「座り仕事」「力仕事なし／少なめ」が該当すれば書く
- 退職理由（雇用が不安定・やりがいがない・職場環境）から逆算して不安を潰す
- 設備（ラジオが流れている、休憩室あり、空調完備）

**軽作業**
- 作業工程、商材の大きさ・重さ、座り仕事か立ち仕事か、力仕事の有無、スタッフ人数
- タイトルは検索されやすい一般語で（シール貼り／梱包／ピッキング／倉庫内作業／検品）
- 退職理由（単調・人間関係・体力的にきつい・作業環境）を意識
- 日払い週払い／短時間OK／Wワーク可／履歴書不要 などがあれば書く

**警備**
- 誘導／監視／巡回など業務を具体的に。1日の流れがあると尚よい
- 拘束時間が長いイメージがあるので、日勤のみ・希望シフト制などを補足
- 早上がりの日給保障、雨天時の給与保障があれば必ず記載
- 直行直帰OK、制服貸与の具体（ファン付き、ダウン、安全靴）

**派遣系（製造）**
- 派遣先だけでなく**雇用主（派遣元）の情報**も重要。安心して応募できるようPR欄を活用
- 勤務時間を「職場カレンダーによる」で済ませない。時間帯・休憩・残業月平均を具体的に
- 記載すべき: 勤務時間帯／休憩／残業月平均○時間／希望シフト制か固定か／日勤のみか夜勤ありか／土日休み／年間休日○日／有給／長期連休

## ペルソナ複製の仕組み

4種類定義し、原稿の裏付けがあるものから上位3つを採用する。

| ペルソナ | 成立条件 |
|---|---|
| 未経験 | `未経験歓迎` タグがある |
| 経験者 | `経験者歓迎` タグがある |
| 収入重視 | 常に成立 |
| 働き方重視 | 土日祝休み・日勤・長期休暇のいずれかがある |

重複判定を避けるため、変種間で以下を変える。事実は変えず「どの事実をどの順で見せるか」で差を作る。

- **タイトル**：3種の構文テンプレート。バッジは変種間で排他的に割り当て
- **仕事内容**：リード文・ポイント列挙・締めを差し替え。元原稿の装飾ヘッダーは収入重視版にのみ残す
- **PR・職場情報欄**：ペルソナごとに異なる既存情報を配置

実行時に類似度を計測して表示する。目安はタイトル30%台・本文50%台。
本文50%が機械的な組み替えの下限で、これ以上下げるには文章そのものの言い換え（AIリライト）が必要。

## 新しい媒体を追加するには

1. エクスポートのヘッダーを調べ、`buildIndex()` が使う英語フィールド名の対応を確認
2. `convertRow()` に項目マッピングを追加
3. `OCCUPATION_RULES` に職種区分の判定ルールを追加（26種のマスタと完全一致必須）
4. その媒体固有の定型文があれば `cleanBoilerplate()` に除去ルールを追加

PDF等の単発案件は `extra_jobs.json` に求人ボックスの列名そのままで書けば合流する。
