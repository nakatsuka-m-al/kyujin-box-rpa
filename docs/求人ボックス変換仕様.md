# 求人ボックス 採用ボード CSV 変換仕様

他媒体（AirWork等）の求人原稿を、求人ボックス「直接投稿（採用ボード）」のCSV一括更新形式へ変換するための仕様。
**この文書だけで変換が再現できるように書いてある**（実装コードが手元になくても可）。

- 実装: `kyujin_box_rpa/scripts/airwork_to_kyujinbox.js` ほか
- 運用ルール・使い方: `kyujin_box_rpa/scripts/README_求人ボックス変換.md`
- 最終確認: 2026-08-27（AirWork 15件 + PDF 1件 → 48件で取り込み成功）

---

## 0. 最初に読むべき鉄則

### 公式マニュアルの列名は信用しない

`https://saiyo.kyujinbox.com/ptr/csvupload_manual.pdf`（ver.1.3）には**列名の誤りが複数ある**。

| マニュアルの記載 | 実際に通る名前 |
|---|---|
| `求人作成日`（仕様表 p.30） | **`求人作成日時`** |
| `特徴`（記入例 p.42） | **`求人の特徴`** |

どちらも「使用できない項目名が含まれています」で弾かれた実績あり。**この2つで実際に2回失敗している。**

### 正解の取得方法

管理画面 → CSV一括更新 → **ダウンロードタブ** から実CSVを1本落とす。
ファイル名は `P-(パートナーID)_saiyoboard_kyujin_(YYYYMMDDHHMM).csv`。
**そのヘッダー行が唯一の正**。列名で迷ったら推測せず必ずこれを取得する。

```

```

```

```


## 4. バリデーション規則

### 文字数上限

| 列 | 上限 |
|---|---|
| 勤務先名 | 100 |
| 求人タイトル | 75 |
| 仕事内容 | 10000（**20文字以上**も必須） |
| この仕事のやりがい | 140 |
| 対象となる方 | 1000 |
| 勤務地_詳細_N | 100 |
| 交通手段・勤務地補足 | 200 |
| 給与補足・福利厚生・受動喫煙防止措置など | 500 |
| 勤務時間・休日 | 500 |
| 選考について | 500 |
| PR・職場情報_見出し_N | 100 |
| PR・職場情報_内容_N | 1000 |
| メモ | 30 |
| 求人ラベル | 1ラベル20文字・1求人10個まで |

### 求人タイトルで使える記号は `・` `／` `「」` のみ

`【】` `｜` `＆` `（）` 半角括弧 `()` `★` `※` `！` 桁区切りカンマ などはすべて不可。

> マニュアルp.28は禁止記号の列挙（`■□▲△▼▽◆◇○◎●♪♭♯★☆＼彡〒〓゜＊*`）だが、
> **実際の運用はより厳しい許可制**。媒体側から「`・／「」` のみ」と案内があった。
> 違反すると**キーワードが自動整形され、タイトルが削除される可能性がある**。

他媒体の元タイトルにも半角括弧が混ざっていることが多いので、必ず変換する。

```
倉庫内作業スタッフ(CDケースの検品・検査)
  → 倉庫内作業スタッフ「CDケースの検品・検査」
```

### 給与

- `給与（上限）` は数値または `上限なし`
- 下限より低い値はエラー
- タイプ別の上限: 時給 30,000 / 日給 200,000 / 月給 1,500,000 / 年収 30,000,000 / 固定報酬 30,000,000
- `非公開` の場合は下限・上限とも空でなければエラー

### 5値カンマ項目

`職場の雰囲気` `仕事のスタイル` `活かせる持ち味` は、**入力するならカンマ4つ（5要素）が必須**。空欄はOK。

- 仕事のスタイル / 活かせる持ち味: 各要素 `1`〜`3`
- 職場の雰囲気: 1〜4要素目が `0`〜`6`、5要素目が年齢層（`20代-30代-40代` のように `-` でつなぐ）

### PR・職場情報

`見出し_N` と `内容_N` は**どちらか一方だけ埋まっているとエラー**。セットで入れるか両方空にする。
削除したい場合は両方に `削除する` と入力（空欄では消えない）。

### その他

| 列 | 規則 |
|---|---|
| 企業ID | `[0-9][a-z][-]` のみ |
| 求人ID | `[0-9][-]` のみ |
| 応募受付の電話番号 | `[0-9][-]` のみ。`(代)` などが入るとエラー |
| 応募時の電話番号を必須入力にする | `する` / `しない` |
| 勤務地_詳細_N | 対になる `勤務地_県_N` が空だとエラー |

## 5. 更新モード

### 求人IDを入れると更新になる

`求人ID` が空 → 新規投稿 / `求人ID` あり → その求人を更新。

### 空欄の列は既存の値を消す（重要）

マニュアルp.12:

> 指定したカラム名に対して空欄となっている部分は、更新前に値が設定されていても
> 入力なしという形で更新されてしまいます。

したがって**更新時は値のある列だけを送る**。全56列を送ると、管理画面で手動設定した写真IDや
職場の雰囲気などが消える。逆に、変更したい列だけに絞ったCSVを送ることは公式に許容されている。

### 求人IDの引き当て方

`メモ` 欄に一意のキーを書き込んでおくと、次回ダウンロードしたCSVと突合できる。
本ツールは `AW:12485617/経験者` の形式（元求人ID + ペルソナ名）で書いている。

### 更新できない列

`求人作成日時` はシステム管理項目で値を更新できない。送らないのが正しい。

## 6. 変換ロジック（AirWork → 求人ボックス）

AirWorkのエクスポートは265列。英語フィールド名が `職種名(title)` の形で併記されているので、
括弧内の英名をキーに索引を作ると扱いやすい。

### 項目マッピング

| 求人ボックス | AirWork | 加工 |
|---|---|---|
| 勤務先名 | `working_location_id_jp` | 表記ゆれを統一 |
| 求人タイトル | `title` | 記号を `・／「」` に整形 |
| 職種区分 | `occupation_id_jp1` | 26種マスタへマッピング |
| 雇用形態 | `job_type_jp` | 7種マスタへマッピング |
| 仕事内容 | `description` | 定型文除去 |
| この仕事のやりがい | `subtitle`（求人キャッチコピー） | 140字。無ければ生成 |
| 対象となる方 | `personal`（求める人材） | |
| 求人の特徴 | 各種 `*_id_name` タグ群 | 62種マスタへ写像 |
| 勤務地_県_1 | `working_location_prefecture` | |
| 勤務地_詳細_1 | `working_location_city_area` | |
| 交通手段・勤務地補足 | `working_location_postcode` ほか | 郵便番号を `〒319-1222` に整形 |
| 給与タイプ | `salary_form_jp` | |
| 給与（下限）/（上限） | `minimum_salary` / `maximum_salary` | |
| 給与補足・福利厚生… | `salary_supplement` + `salary_example` + `welfare` + 喫煙情報 | 結合して500字 |
| 勤務時間・休日 | `working_time_supplement` + `holiday` | 結合して500字 |
| 応募・選考についての必要項目 | `entry_form_type_jp` | 3種マスタへ |
| 応募受付の電話番号 | `contact_phone` | 数字とハイフンのみ |
| 選考について | `selection_flow_id_name` + `selection_flow` | |
| メモ | `job_offer_id` | 更新時の突合キー |

### 職種区分の判定は「職種名 → タイトル → 仕事内容」の順に段階評価する

一括で突き合わせると誤判定する。実例:

> 「汎用フライス盤のマシンオペレーター」の仕事内容に**「機械周辺の清掃」**という
> 付随作業の記載があり、`警備・清掃・点検` と判定された。

信頼度の高い順に評価し、最初に当たったものを採用する。ルール自体も製造系を先に置く。

### 結合フィールドは文字数超過時に文の切れ目で切る

`勤務時間・休日` `給与補足` は500字上限。元原稿は超えることが多い。
単純に切ると文が壊れるので、上限の60%以降にある `\n` か `。` を探して切る。

### 媒体固有の定型文を除去する

AirWorkの原稿には求人ボックスでは意味をなさない定型文が入っている。

**削除するもの**

```
※※登録不要で求人内容チェック！※※
画像のQRコードを長押しして読み込めば、
登録なしでも求人の中身が読めます！        ← 求人ボックスに画像QRは出ない

※QRコードは
(株)デンソーウェーブの登録商標です。      ← QR案内を消すので不要

＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
（中身のない空行が10行以上続く）        ← 枠だけ大きくなる
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
```

**絶対に削除しないもの**

```
※労働者派遣業（派）08-300957            ← 労働者派遣法上の表示事項
```

処理は空行区切りのブロック単位で行うが、**法定表示を含むブロックだけは行単位で処理する**。
QRの商標表記と許可番号が同じブロックに同居している原稿があり、ブロックごと消すと巻き添えになる。

同様に、`《株式会社◯◯》` で始まる会社紹介ブロックを「装飾ヘッダー」と誤判定して消さないこと。
装飾判定は**ブロック内の全行が飾り行の場合のみ**とする。

## 7. ペルソナ複製（1原稿 → 3原稿）

同一求人を訴求角度違いで複数出す場合の設計。

### 4種類を定義し、原稿の裏付けがあるものから上位3つを採用

| ペルソナ | 成立条件 | 訴求軸 |
|---|---|---|
| 未経験 | `未経験歓迎` タグがある | 経験不問・研修・制服 |
| 経験者 | `経験者歓迎` タグがある | 経験が活きる・残業代 |
| 収入重視 | 常に成立 | 給与・週払い・残業代 |
| 働き方重視 | 土日祝休み / 日勤 / 長期休暇のいずれか | 休日・日勤・通勤 |

「未経験」「経験者」は片方しか成立しない原稿が多いため、4つ目の「働き方重視」で3本を確保する。

> 求人ボックス公式ガイドも「経験者優遇・未経験者も歓迎」の併記をNGとしており、
> 経験者向けは専門用語、未経験者向けは教育体制と平易な説明、と分けることを推奨している。
> ペルソナ分割はこの指摘に沿っている。

### 重複判定を避けるための差別化

同一企業・同一勤務地・同一給与は変えられないので、**文面で差を作る**。
ただし**事実は変えない**。「どの事実をどの順で見せるか」だけを変える。

- **タイトル**: 3種の構文テンプレート。バッジは変種間で**排他的に**割り当てる

  ```
  「未経験歓迎・社会保険完備」施設管理・ドラム缶移動スタッフ
  施設管理・ドラム缶移動スタッフ「那珂郡東海村舟石川」／日給12000円
  土日祝休み・日勤のみ／施設管理・ドラム缶移動スタッフ
  ```

- **仕事内容**: リード文・ポイント列挙・締めをペルソナ別に差し替え。
  元原稿の装飾ヘッダー（`＼＼【時給1500円～】／／` 等）は収入重視版にのみ残す
- **PR・職場情報欄**: ペルソナごとに異なる既存情報を別の見出しで配置

### 効果の目安

| 指標 | 対策前 | 対策後 |
|---|---|---|
| タイトル類似度 | 65.9% | 32〜41% |
| 仕事内容類似度 | **100%** | 51〜62% |

本文50%台が機械的な組み替えの下限。これ以上下げるには文章そのものの言い換え（AIリライト）が必要。

### 元データ側の重複も検出する

実際に、AirWork側にすでに重複求人が2組あった（本文100%一致 / タイトル100%一致）。
複製する前に統廃合しないと、そもそもその組が重複扱いになる。

## 8. 法令上の制約（必須）

### 年齢による絞り込みを書かない

**雇用対策法10条**により募集・採用時の年齢制限は原則禁止。
「39歳まで」のような記載は不可。例外規定はあるが期間の定めのない雇用契約が条件で、
派遣・有期には使えない。

若年層からの応募を増やしたい場合は、**制限ではなく訴求内容**で寄せる
（未経験から始められる / 高収入 / 土日祝休みでプライベート両立 など）。

### 性別による限定を書かない

**男女雇用機会均等法5条**により募集・採用時の性別限定は原則禁止。
元原稿に「性別:男性」とあっても出力しない。

重量物の取り扱い等で女性の就業制限に該当する業務がある場合は、性別ではなく
**業務内容として**記載する（例:「20kg程度の重量物の取り扱いあり」）。これなら適法かつミスマッチも防げる。

### 原稿に無い事実を足さない

装飾文言・訴求文は、すべて元原稿から抽出した事実に裏付けがある場合のみ出力する。
「20代・30代活躍中」のような記載も、実データがなければ書かない。

## 9. 求人ボックス推奨の原稿ルール（**必須ではない**）

出典は求人ボックス提供の公式ガイド4資料。**守らなくてもアップロードは通る。**
機械的に強制すると原稿が痩せたり変種のタイトルが同一化したりして逆効果になるので、
**推奨より実害の回避を優先する**（30字に詰めるためにバッジを削って3変種が同じタイトルになるくらいなら、35字でも差別化を取る）。

### タイトル

- **30文字以内**が目標（検索結果画面で見切れる）。CSV上限は75文字
- 職種名は具体的に。✕「警備員」→ ○「日勤のみの施設内警備スタッフ」
- 未経験向けなら未経験者が想像できる言葉に。✕「インサイドセールス」→ ○「取引先への法人営業・訪問なし」
- 経験・資格が必須なら明記（`CADオペレーター／経験3年以上`）。アンマッチなクリックを減らせる

### 抽象語を避け、具体・定量で書く

| ✕ 抽象 | ○ 具体 |
|---|---|
| 福利厚生充実 | 社食1食130円、住宅手当月5万、賞与去年度実績6か月分 |
| 安定・高収入 | プライム上場、業界シェアトップ、入社1年目から420万可 |
| シフト制 | 連休OKのシフト制、平均月8日休みのシフト制 |

### メリットキーワードの強弱（強い順）

- 土日休み・土日祝休み ＞ 完全週休2日制 ＞ 週休2日制
- 残業なし ＞ 残業ほぼなし ＞ 残業少なめ
- 希望シフト制・自由シフト制 ＞ 希望休OK ＞ 希望休を反映
- 有給自由取得・消化率○% ＞ 有給取得しやすい ＞ 有給休暇あり

### 使わないワード

- **「急募」は非推奨** —「いつでも入れる」「なかなか採用できない」「すぐ辞める」という印象を与える。
  代用: 「即日勤務可」「事業好調／積極増員中」
- **「経験者優遇・未経験者も歓迎」はNG** — 見せ方を分ける

### タイトルに書く優先度が低いもの

本文に記載があれば求人ボックス側で一覧に自動表示される。タイトル枠を使うのはもったいない。

- 正社員で本文に賞与・昇給の記載 → 「賞与あり・昇給あり」が自動表示
- パート/アルバイトで本文に交通費の記載 → 「交通費支給」が自動表示

ただし「賞与年3回」「去年度実績6か月分」のように大きなメリットになる場合は書く。

### 応募フォームの使い分け

入力項目が多いほど応募のハードルが上がる。

| 設定 | 向いているケース |
|---|---|
| 氏名・連絡先のみ | 経験・学歴不問、アルバイト・パート、大量募集、採用競争が激しい業界 |
| 基本情報 | 正社員募集、応募条件あり |
| 基本情報＋職務経歴 | 書類選考を実施、応募を絞りたい |

### 写真が掲載順位に影響する

アルゴリズム更新により**画像の有無が掲載順位の要素**になっている。職場写真は6枚まで登録可能。
CSVには `写真ID`（アカウントに紐づくID）しか入れられないので、実質は管理画面での登録が必要。

### 職種別の押さえどころ

**製造・機械オペレーター** — 具体的な作業工程、扱う製品、**商材の大きさ・重さ**、スタッフの人数・年齢層、
「座り仕事」「力仕事なし」、設備（空調完備・休憩室）

**軽作業** — 作業工程、商材の重さ、座り/立ち、力仕事の有無。タイトルは検索されやすい一般語で
（シール貼り／梱包／ピッキング／倉庫内作業／検品）

**警備** — 誘導/監視/巡回を具体的に。1日の流れ。拘束時間が長いイメージへの対処（日勤のみ等）。
早上がりの日給保障、雨天時の給与保障は必ず書く

**派遣系** — 派遣先だけでなく**雇用主（派遣元）の情報**も重要。勤務時間を「職場カレンダーによる」で
済ませず、時間帯・休憩・残業月平均を具体的に

## 10. 検証手順

アップロード前に以下を機械的に検査する。

1. ヘッダー行が公式ダウンロードCSVと**バイト単位で一致**するか
2. 必須列がすべて埋まっているか
3. マスタ値（職種区分・雇用形態・求人の特徴・都道府県・給与タイプ・応募必要項目・求人ステータス）の完全一致
4. 文字数上限
5. 求人タイトルの使用文字（かな・漢字・英数・長音・`・／「」` 以外が無いか）
6. 給与のタイプ別上限、下限 ≤ 上限
7. 5値カンマ項目のカンマ数
8. PR・職場情報の見出し／内容のペア
9. 年齢・性別による絞り込み表現が混入していないか
10. 変種間の類似度（タイトル・本文）と、元データ側の重複
